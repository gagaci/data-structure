Why does this work?

The problem: given the heads of two singly linked lists that may merge and share a common tail, return the first shared node — or null if they never touch. The lists can be different lengths, which is exactly what makes a naive "walk them in lock-step" approach fail: the pointers are misaligned by the length difference.

The two-pointer trick fixes the misalignment for free:

  • tempA walks all of list A, then jumps to the head of list B.
  • tempB walks all of list B, then jumps to the head of list A.

Let a be the length of A's unique part, b be B's unique part, and c the shared tail. After the crossover, tempA has walked a + c + b steps and tempB has walked b + c + a steps to reach the same point. Both sums are equal, so the two pointers become perfectly aligned and land on the first shared node at the same moment.

The null case falls out automatically. If the lists never intersect, then c = 0. Both pointers still walk a + b steps and then hit null on the same iteration — so tempA == tempB == null, the while loop ends, and the method returns null. No special-casing needed. The reference comparison tempA != tempB is doing the real work here, not a value comparison.
